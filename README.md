# HaraTomo

**HaraTomo（はらとも）** は、胃腸が弱い人のための「自分のことを知っている食生活AIエージェント」を目指すアプリです。

食事・腹痛・下痢・膨満感などの症状だけでなく、冷え、睡眠、ストレス、運動、外食なども自然な会話や音声で記録し、ユーザーごとの傾向を少しずつ学習します。

将来的には、記録だけで終わらず、献立、買い物リスト、冷蔵庫在庫、賞味期限、外食時のメニュー選びまで一つのエージェントが支援します。

> 目標は「食事を記録するアプリ」ではなく、  
> **記録そのものをAIとの会話の裏側に隠し、自分のお腹に合う生活を一緒に作ること**。

---

## 想定ユーザー

- お腹を壊しやすいが、原因がよく分からない人
- IBS（過敏性腸症候群）などで日々の食事と体調の関係を把握したい人
- 食事記録アプリが面倒で続かなかった人
- 食事だけでなく、冷え・睡眠・ストレス等も含めて振り返りたい人
- 自分に合う食生活をAIに継続的に学習してほしい人

HaraTomoは診断や治療を行う医療機器ではなく、**日々の記録・振り返り・生活支援**を目的とします。

---

## 解決したい課題

従来の食事・症状記録では、次のような問題があります。

1. 毎食入力するのが面倒
2. 食品名だけでは「冷え」「寝不足」「ストレス」などを扱えない
3. 食事と症状の時間差を自分で振り返るのが難しい
4. 相関があっても、本当に原因なのか判断しにくい
5. 記録しても、次の食事や献立に活かされない
6. 献立・買い物・在庫管理が別アプリに分断されている

HaraTomoでは、**入力 → 個人分析 → 提案 → 次の行動 → 再記録**を一つのループにします。

## コア体験

### 1. 音声・自然文でまとめて記録

例：

> 「昼にラーメン。15時くらいから冷房でかなり冷えた。18時に下痢。腹痛は6くらい。」

AIが自動で構造化します。

- 12:30 食事: ラーメン
- 15:00 要因: 冷え（強）
- 18:00 症状: 下痢
- 18:00 症状: 腹痛 6/10

ユーザーは項目ごとにフォーム入力する必要がありません。

### 2. 自分専用のユーザーモデル

AIは長期的に、以下を分けて覚えます。

- 食の好み・苦手
- 食事履歴
- 症状履歴
- 冷え・睡眠・ストレス・運動などの生活要因
- 外食履歴
- 「この条件の組み合わせで症状が出やすい」といった傾向
- 傾向の信頼度・観測回数
- 献立・冷蔵庫・買い物の状況

一般論よりも、**本人の観測データを優先して振り返れること**を重視します。

### 3. 原因を断定しない分析

「牛乳のあとに腹痛が3回あった」だけで、AIが「牛乳が原因」と断定しないようにします。

例：

> 牛乳を摂った12回のうち3回で6時間以内に腹痛がありました。  
> ただし、その3回はいずれも睡眠時間が短く、現時点では牛乳単独の影響とは判断できません。

**相関・仮説・確信度を分けて提示する**ことを基本方針とします。

## MVP

最初は機能を広げすぎず、以下に集中します。

### 必須

- [ ] テキストによる自然文入力
- [ ] 音声入力 → 文字起こし
- [ ] AIによる食事・症状・生活要因の構造化
- [ ] タイムライン表示
- [ ] 食事ログ
- [ ] 症状ログ
- [ ] 冷え・睡眠・ストレス等の要因ログ
- [ ] 後から修正できる確認UI
- [ ] 個人履歴を利用したAIチャット
- [ ] 過去ログ検索
- [ ] 食事と症状の時間的関連の簡易集計
- [ ] データ削除・エクスポート

### MVPではやらない

- 医学的診断
- 病名の断定
- 医薬品の処方・変更指示
- 完全自動の原因特定
- 大規模な栄養管理
- 冷蔵庫在庫の完全自動管理

## 将来機能

### Phase 2: 外食支援

- 店名・メニュー名からWeb上の公式情報を取得
- 栄養成分・アレルゲン・原材料等の保存
- メニュー写真から候補を認識
- 過去の本人の反応を参考にメニュー選択を支援

### Phase 3: 献立

- 1週間分の献立生成
- 好み・調理時間・予算・胃腸履歴を考慮
- 献立をそのまま食事予定として登録
- 「予定どおり食べた」場合はワンタップで食事記録
- 実際に違うものを食べた場合だけ差分を修正

### Phase 4: 買い物リスト

- 献立から必要食材を抽出
- 在庫との差分から買い物リストを生成
- 店舗別・カテゴリ別に整理

### Phase 5: 冷蔵庫・食品在庫

- 食品名、数量、購入日、賞味期限
- レシート・バーコード・写真から追加
- 献立を実行したら在庫を自動減算
- 賞味期限の近い食材を献立で優先

### Phase 6: 食生活エージェント

- 今日の体調・予定・睡眠・在庫を踏まえた提案
- 「今日はお腹が不安定なので夕食を変更しますか？」のような先回り支援
- 献立変更 → 買い物リスト → 在庫 → 食事予定まで連動
- ユーザーごとの傾向を継続更新

## AI設計の基本方針

### LLMに任せること

- 自然文の解釈
- 音声文字起こし結果の整理
- エンティティ抽出
- 会話
- ログの要約
- 仮説の言語化
- 献立候補の生成
- ユーザーへの自然な確認質問

### コードで保証すること

- 日時
- 数値集計
- 症状発生率
- 時間窓の集計
- 保存・削除
- データ整合性
- 在庫数量
- 賞味期限
- AIが参照した元データ

**数値そのものをLLMの記憶だけに頼らない**ことを原則にします。

## プロダクト原則

1. **入力を増やさない**
2. **AIが勝手に断定しない**
3. **なぜその提案をしたか説明できる**
4. **本人の履歴と一般知識を混同しない**
5. **ユーザーがAIの記憶を確認・修正・削除できる**
6. **予定済みの情報は再入力させない**
7. **健康データを広告最適化のために利用しない**
8. **データの正しさはLLMではなくコードとDBで担保する**
