# HaraTomo

**HaraTomo（はらとも）** は、胃腸が弱い人のための「自分のことを知っている食生活AIエージェント」を目指すWebアプリです。

食事・腹痛・下痢・膨満感だけでなく、冷え・睡眠・ストレスなども自然文でまとめて記録し、ユーザー自身の履歴から「どんな条件のときに調子を崩しやすいか」を振り返れるようにします。

将来的には、献立、買い物リスト、冷蔵庫在庫、賞味期限、外食時のメニュー選びまで同じエージェントにつなげます。

> 目標は「毎回フォームに食事を記録すること」ではなく、  
> **自分のお腹に関する出来事をAIに話すだけで、記録と振り返りが済むこと**。

---

## 想定ユーザー

- お腹を壊しやすいが、原因がよく分からない人
- IBSなどで食事と体調の関係を把握したい人
- 食事記録アプリが面倒で続かなかった人
- 冷え・睡眠・ストレスなども含めて振り返りたい人

HaraTomoは診断や治療を目的とする医療機器ではなく、**日々の記録・振り返り・生活支援**を目的とします。

---

## MVPで確認したい価値

最初から「食生活OS」を作るのではなく、まず次の1点を検証します。

**自然文で簡単に記録すると、自分のお腹の傾向を後から振り返れることに価値があるか。**

例:

> 「昼にラーメン。夕方かなり冷えて、20時に下痢。腹痛は6くらい。」

AIが以下のように分けます。

- 食事: ラーメン
- 要因: 冷え
- 症状: 下痢
- 症状: 腹痛 6/10

ユーザーは保存前に修正できます。

## MVP

### P0: 最初に作るもの

- [ ] 自然文入力
- [ ] AIによる食事・症状・生活要因の構造化
- [ ] 構造化結果の確認・修正
- [ ] SQLiteへの保存
- [ ] 時系列タイムライン
- [ ] ログの編集・削除
- [ ] 簡単な傾向表示
  - 症状の前6時間に何があったか
  - 各要因の観測回数
  - 症状が続いた回数

### P1: P0が動いた後

- [ ] 音声入力
- [ ] 自分の履歴についてAIに質問
- [ ] 簡単なプロフィール・好みの記憶
- [ ] JSONエクスポート

### MVPではやらない

- ログイン・複数ユーザー対応
- Vector DB / Embedding
- 高度なAI Memory
- 因果推論
- 高度な確信度スコア
- 外食Web検索
- 献立生成
- 冷蔵庫在庫
- 賞味期限
- 買い物リスト
- Push通知
- HealthKit / Siri連携
- バックグラウンドジョブ
- 監査ログ
- 複雑なマイクロサービス構成

---

## MVP技術スタック

- **Web:** Next.js + TypeScript
- **DB:** SQLite
- **ORM:** Drizzle ORM
- **Validation:** Zod
- **AI:** LLM API
- **UI:** Next.js内で完結
- **構成:** 単一Webアプリ

MVPでは、Web・API・DBを別リポジトリや別サービスへ分けません。

```text
Browser
  ↓
Next.js
  ├─ UI
  ├─ Server Action / Route Handler
  ├─ LLM API
  └─ SQLite
```

---

## AI設計の基本方針

### LLMに任せる

- 自然文の解釈
- 食事・症状・生活要因への分解
- ユーザー向けの説明文

### コードで処理する

- 保存・編集・削除
- 日時処理
- 件数
- 時間差
- 症状発生前のイベント抽出
- 集計

**LLMにDB全体を渡して、数値を推測させない。**

## 将来像

MVPで「簡単に記録できる」「自分の傾向が分かる」ことを確認できたら、順次広げます。

1. 音声で記録
2. 外食情報の取得
3. 1週間の献立
4. 献立を食事ログとして自動利用
5. 買い物リスト
6. 冷蔵庫在庫・賞味期限
7. 体調・予定・在庫まで見て提案する食生活エージェント

---

## プロダクト原則

1. **入力を増やさない**
2. **AIが原因を断定しない**
3. **本人の記録とAIの推測を分ける**
4. **数値はコードで計算する**
5. **ユーザーが記録を修正・削除できる**
6. **複雑な仕組みは価値が確認できてから追加する**
