# HaraTomo Product

## 1. 誰のためのアプリか

HaraTomoは、胃腸が弱く、食事・体調・生活要因の関係を振り返りたい人のためのWebアプリ。

ユーザーは医療知識を持っていることを前提にしない。細かいフォーム入力を継続できることも前提にしない。

## 2. ユーザーがしたいこと

中心となるJobは次の1つ。

> お腹に関する出来事を普段の言葉で話し、あとから自分の傾向を簡単に振り返る。

そのために、MVPでは次を可能にする。

- 食事・症状・生活要因を自然文でまとめて記録する
- AIが記録候補へ整理する
- 曖昧な部分だけ確認・修正する
- 時系列で履歴を見る
- 症状前6時間に何があったかを簡単に振り返る

## 3. コア体験

HaraTomoの中心は「入力フォーム」ではなく「会話に近い記録」。

理想的な流れ:

```text
思い出したことを書く
  ↓
AIが整理
  ↓
必要な箇所だけ確認
  ↓
保存
  ↓
あとでタイムラインと傾向を確認
```

ユーザーに構造化を強要しない。構造化はアプリ側が担当する。

## 4. MVPで検証する価値

**自然文で低負担に記録できれば、自分のお腹の傾向を継続的に振り返る価値が生まれるか。**

MVPでは、AIエージェントの多機能さよりも次を優先する。

1. 記録が面倒でない
2. 記録内容をユーザー自身が確認できる
3. 後から履歴を探しやすい
4. AIが原因を断定しない
5. UIが記録の邪魔をしない

## 5. MVPの対象

P0:

- 自然文入力
- LLMによるEventDraft抽出
- Jevによる固定候補の分類・検証
- Zod validation
- 必要箇所の確認・修正
- SQLite保存
- Timeline
- CRUD
- 症状前6時間のSimple Insight

P1:

- 音声入力
- 自分の履歴へのAI質問
- 簡単なプロフィール
- JSONエクスポート

詳細は [requirements.md](requirements.md) を参照。

## 6. MVPでやらないこと

- ログイン・複数ユーザー
- 献立
- 買い物リスト
- 冷蔵庫在庫
- 賞味期限
- 外食検索
- 高度なMemory
- Vector DB
- 因果推論
- 医学的診断
- Generic Agent Framework

「将来必要かもしれない」だけでは追加しない。

## 7. 将来像

MVPで記録と振り返りの価値を確認できた後、同じユーザー理解を以下へ広げる。

- 献立
- 買い物
- 冷蔵庫在庫
- 賞味期限
- 外食時の選択
- 予定や体調を考慮した提案

目標は、機能を増やすことではなく、**自分の食生活と体調を知っているAIエージェント**へ育てること。

## 8. プロダクト判断の優先順位

迷ったら次の順で判断する。

1. 記録負担を減らせるか
2. ユーザーが自分の記録を理解・修正できるか
3. 振り返りに役立つか
4. 誤解や過度な断定を増やさないか
5. MVPに本当に必要か

見栄えのためだけに機能や情報を増やさない。
